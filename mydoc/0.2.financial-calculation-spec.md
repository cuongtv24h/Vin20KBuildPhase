# 2. QUY CHUẨN SỐ HỌC (ARITHMETIC CONTRACT)

### 2.1 Kiểu Dữ liệu & Độ chính xác Số học
- **Tuyệt đối cấm số thực dấu phẩy động (`float` / `double`):** Mọi tính toán tiền tệ nội bộ bắt buộc sử dụng module `decimal.Decimal` với context tối thiểu 28 chữ số có nghĩa:
  ```python
  from decimal import Decimal, ROUND_HALF_UP, getcontext
  getcontext().prec = 28
  ```
- **Đơn vị tiền tệ:** Đồng Việt Nam (VNĐ). Độ chính xác xuất bản: **0 chữ số thập phân (`Decimal('1')`)**. Cấm số lẻ hào/xu.
- **Thuật toán làm tròn chuẩn mực kế toán Việt Nam:**
  ```python
  def round_vnd(amount: Decimal) -> int:
      return int(amount.quantize(Decimal('1'), rounding=ROUND_HALF_UP))
  ```

### 2.2 Quy chuẩn Thời gian & Dải Ngày Hiệu lực
- **Múi giờ chuẩn:** `Asia/Ho_Chi_Minh` (UTC+7:00).
- **So sánh ngày theo chuẩn ISO-8601:** Sử dụng kiểu dữ liệu `datetime.date` (`YYYY-MM-DD`).
- **Dải ngày hiệu lực đóng hai đầu (Inclusive Interval):**
  $$\text{effective\_from} \le T_{\text{tx}} \le \text{effective\_to}$$
  Triệt tiêu hoàn toàn lỗi so sánh microsecond $23:59:59.999999$.

# 3. HỢP ĐỒNG ĐẦU VÀO SỐ HỌC (POLICY-DRIVEN INPUT CONTRACT & PROVENANCE)

Động cơ tính toán chỉ tiếp nhận `PricingCalculationInput` đã được khối `Policy Intelligence (C-02)` bóc tách và thẩm định xong. Động cơ **không hard-code** cấu hình kịch bản mà nhận cấu hình kịch bản động từ chính sách:

```python
from pydantic import BaseModel, Field, model_validator
from datetime import date
from typing import Optional, Any
from decimal import Decimal
from enum import Enum

class ScenarioType(str, Enum):
    STANDARD_PROGRESS = "STANDARD_PROGRESS"
    EARLY_95 = "EARLY_95"
    BANK_LOAN_HTLS = "BANK_LOAN_HTLS"

class QuoteWorkflowStatus(str, Enum):
    DRAFT = "DRAFT"
    VALIDATING = "VALIDATING"
    CALCULATING = "CALCULATING"
    READY_FOR_REVIEW = "READY_FOR_REVIEW"
    APPROVED = "APPROVED"
    REJECTED = "REJECTED"
    ABSTAINED = "ABSTAINED"
    BLOCKED = "BLOCKED"              # Phong tỏa do tranh chấp căn, double-booking, hoặc rào cản nghiệp vụ
    PDF_ISSUED = "PDF_ISSUED"

class StructuredPolicyReference(BaseModel):
    policy_id: str
    policy_version: str
    clause_id: str
    page_number: int
    source_file_sha256: str
    effective_from: date
    effective_to: date

class InstallmentRule(BaseModel):
    installment_number: int = Field(..., ge=1, le=30)
    milestone_name: str = Field(..., min_length=1)
    days_from_deposit: int = Field(..., ge=0, description="Số ngày tính từ ngày đặt cọc (deposit_date)")
    
    # Funding Allocation Breakdown
    customer_equity_ratio: Decimal = Field(default=Decimal("0"), ge=0, le=1)
    bank_disbursement_ratio: Decimal = Field(default=Decimal("0"), ge=0, le=1)
    maintenance_fee_ratio: Decimal = Field(default=Decimal("0"), ge=0, le=1)
    
    is_handover: bool = Field(default=False)
    is_reconciliation: bool = Field(default=False)
    
    @property
    def payment_ratio(self) -> Decimal:
        return self.customer_equity_ratio + self.bank_disbursement_ratio

class PaymentScenarioConfig(BaseModel):
    scenario_type: ScenarioType
    scenario_name: str
    installment_rules: list[InstallmentRule]
    deposit_amount_vnd: int = Field(..., ge=0, description="Bắt buộc nạp từ giao dịch (Simulation fallback: 100,000,000)")
    bank_financing_rate: Decimal = Field(default=Decimal("0.0000"), ge=0, le=1)
    customer_equity_rate: Decimal = Field(default=Decimal("1.0000"), ge=0, le=1)
    interest_support_months: int | None = None
    principal_grace_months: int | None = None
    policy_reference: StructuredPolicyReference | None = None

    @model_validator(mode="after")
    def validate_scenario_configuration(self) -> "PaymentScenarioConfig":
        # 1. Kiểm tra tổng tỷ lệ vốn
        if (self.bank_financing_rate + self.customer_equity_rate) != Decimal("1.0000"):
            raise ValueError(f"Scenario {self.scenario_type}: Tổng bank_financing_rate + customer_equity_rate phải bằng 1.0000.")
            
        rules = self.installment_rules
        if not rules:
            raise ValueError(f"Scenario {self.scenario_type}: Danh sách installment_rules không được rỗng.")

        # 2. Invariant Reconciliation: Đúng 1 đợt reconciliation
        recon_rules = [r for r in rules if r.is_reconciliation]
        if len(recon_rules) != 1:
            raise ValueError(f"Scenario {self.scenario_type}: Bắt buộc phải có DUY NHẤT 1 đợt reconciliation (tìm thấy {len(recon_rules)}).")

        # 3. Invariant Handover: Đúng 1 đợt bàn giao
        handover_rules = [r for r in rules if r.is_handover]
        if len(handover_rules) != 1:
            raise ValueError(f"Scenario {self.scenario_type}: Bắt buộc phải có DUY NHẤT 1 đợt bàn giao nhà (tìm thấy {len(handover_rules)}).")

        # 4. Invariant Installment Numbering: Tăng liên tục 1..N
        numbers = [r.installment_number for r in rules]
        expected_numbers = list(range(1, len(rules) + 1))
        if numbers != expected_numbers:
            raise ValueError(f"Scenario {self.scenario_type}: Thứ tự installment_number phải liên tục từ 1 đến {len(rules)}, hiện tại: {numbers}.")

        # 5. Invariant Timeline Monotonicity: Ngày đợt sau >= đợt trước
        days_seq = [r.days_from_deposit for r in rules]
        if days_seq != sorted(days_seq):
            raise ValueError(f"Scenario {self.scenario_type}: Tiến độ days_from_deposit phải đơn điệu không giảm.")

        # 6. Invariant Maintenance Fee: Toàn bộ 100% KPBT phải được thu (thông thường tại handover)
        total_kpbt_ratio = sum(r.maintenance_fee_ratio for r in rules)
        if total_kpbt_ratio != Decimal("1.0000"):
            raise ValueError(f"Scenario {self.scenario_type}: Tổng maintenance_fee_ratio phải bằng 1.0000 (hiện tại: {total_kpbt_ratio}).")

        # 7. Invariant Equity Allocation: Tổng vốn tự có các đợt không reconciliation phải <= customer_equity_rate
        non_recon_equity = sum(r.customer_equity_ratio for r in rules if not r.is_reconciliation)
        if non_recon_equity > self.customer_equity_rate:
            raise ValueError(f"Scenario {self.scenario_type}: Tổng vốn tự có các đợt trước ({non_recon_equity}) vượt quá trần cấu hình ({self.customer_equity_rate}).")

        # 8. Invariant Bank Allocation: Tổng ngân hàng giải ngân các đợt không reconciliation phải <= bank_financing_rate
        non_recon_bank = sum(r.bank_disbursement_ratio for r in rules if not r.is_reconciliation)
        if non_recon_bank > self.bank_financing_rate:
            raise ValueError(f"Scenario {self.scenario_type}: Tổng giải ngân ngân hàng ({non_recon_bank}) vượt quá trần cấu hình ({self.bank_financing_rate}).")

        return self

class PricingCalculationInput(BaseModel):
    unit_code: str
    deposit_date: date                                  # Ngày ký thỏa thuận đặt cọc
    contract_signing_date: date                         # Ngày ký Hợp đồng Mua bán chính thức
    listed_price_vnd: int = Field(..., gt=0)
    deposit_amount_vnd: int = Field(..., ge=0, description="Tiền cọc thực tế đã nộp")
    resolved_policy_snapshot_id: str
    source_policy_hash: str
    approved_benefits: list['BenefitApplicationRule']
    scenario_configs: list[PaymentScenarioConfig]       # Nạp cấu hình kịch bản từ chính sách
    tax_vat_rate: Decimal = Field(default=Decimal('0.1000'))
    maintenance_fee_rate: Decimal = Field(default=Decimal('0.0200'))
    max_discount_rate: Decimal = Field(default=Decimal('0.3500'))
    max_total_discount_cap_rate: Decimal = Field(default=Decimal('0.4000'))
    calculation_spec_version: str = "2.5"

    @model_validator(mode="after")
    def validate_dates(self) -> "PricingCalculationInput":
        if self.contract_signing_date < self.deposit_date:
            raise ValueError(f"Ngày ký HĐMB ({self.contract_signing_date}) không được sớm hơn ngày đặt cọc ({self.deposit_date}).")
        return self
```

```python
class BenefitCategory(str, Enum):
    CASH_DISCOUNT = "CASH_DISCOUNT"      # Chiết khấu tiền mặt trực tiếp
    IN_KIND_GIFT = "IN_KIND_GIFT"        # Quà tặng hiện vật (Vàng SJC, Nội thất, Xe điện)
    VOUCHER = "VOUCHER"                  # Phiếu mua hàng / Voucher
    SERVICE_WAIVER = "SERVICE_WAIVER"    # Miễn phí dịch vụ quản lý vận hành

class BenefitType(str, Enum):
    FIXED_CASH = "FIXED_CASH"            # Giảm trừ tiền mặt cố định vào Base_1
    PERCENTAGE = "PERCENTAGE"            # Chiết khấu tỷ lệ % cộng dồn (Additive)
    IN_KIND = "IN_KIND"                  # Quà tặng hiện vật
    VOUCHER = "VOUCHER"                  # Phiếu ưu đãi
    SERVICE_WAIVER = "SERVICE_WAIVER"    # Miễn phí quản lý dịch vụ

class CalculationBase(str, Enum):
    LISTED_PRICE = "LISTED_PRICE"
    PRICE_AFTER_FIXED = "PRICE_AFTER_FIXED"

class ValuationStatus(str, Enum):
    APPROVED = "APPROVED"       # Đã có chứng thư/hóa đơn định giá chính thức -> Tính vào benefit value & objective
    PENDING = "PENDING"         # Đang chờ kế toán thẩm định -> Hiển thị ghi chú, KHÔNG tính vào objective
    UNVALUED = "UNVALUED"       # Quà tặng thuần túy, chưa có giá trị quy đổi tiền tệ -> Không quy đổi

VALID_BENEFIT_MAPPING = {
    BenefitCategory.CASH_DISCOUNT: {BenefitType.FIXED_CASH, BenefitType.PERCENTAGE},
    BenefitCategory.IN_KIND_GIFT: {BenefitType.IN_KIND},
    BenefitCategory.VOUCHER: {BenefitType.VOUCHER},
    BenefitCategory.SERVICE_WAIVER: {BenefitType.SERVICE_WAIVER}
}

class BenefitApplicationRule(BaseModel):
    benefit_id: str
    benefit_type: BenefitType
    category: BenefitCategory
    fixed_deduction_vnd: int = Field(default=0, ge=0)
    discount_rate: Decimal = Field(default=Decimal("0.0000"), ge=0, le=1)
    calculation_base: CalculationBase = CalculationBase.PRICE_AFTER_FIXED
    application_order: int = Field(default=1, ge=1, description="Thứ tự ưu tiên áp dụng hạn mức và kiểm toán")
    valuation_status: ValuationStatus
    price_deduction_authorized: bool    # CHỈ ĐƯỢC PHÉP TRỪ GIÁ KHI ĐƯỢC CHÍNH SÁCH ỦY QUYỀN
    source_policy_clause: StructuredPolicyReference

    @model_validator(mode="after")
    def validate_benefit_fields(self) -> "BenefitApplicationRule":
        # 1. Ma trận tương thích Category - Type
        allowed_types = VALID_BENEFIT_MAPPING.get(self.category, set())
        if self.benefit_type not in allowed_types:
            raise ValueError(
                f"Benefit {self.benefit_id}: category '{self.category}' "
                f"không tương thích với benefit_type '{self.benefit_type}'. "
                f"Các type hợp lệ: {allowed_types}"
            )
            
        # 2. Nếu không được ủy quyền trừ giá thì cấm có số tiền trừ hoặc tỷ lệ chiết khấu
        if not self.price_deduction_authorized:
            if self.fixed_deduction_vnd > 0 or self.discount_rate > Decimal("0.0000"):
                raise ValueError(
                    f"Benefit {self.benefit_id}: price_deduction_authorized=False "
                    f"nhưng lại có fixed_deduction_vnd={self.fixed_deduction_vnd} hoặc discount_rate={self.discount_rate}."
                )
        # 3. FIXED_CASH bắt buộc số tiền > 0
        if self.benefit_type == BenefitType.FIXED_CASH and self.fixed_deduction_vnd <= 0:
            raise ValueError(f"Benefit {self.benefit_id}: FIXED_CASH yêu cầu fixed_deduction_vnd > 0.")
        # 4. PERCENTAGE bắt buộc discount_rate > 0
        if self.benefit_type == BenefitType.PERCENTAGE and self.discount_rate <= Decimal("0.0000"):
            raise ValueError(f"Benefit {self.benefit_id}: PERCENTAGE yêu cầu discount_rate > 0.")
        # 5. Quà tặng hiện vật chỉ được trừ giá khi có ValuationStatus.APPROVED
        if self.benefit_type == BenefitType.IN_KIND and self.price_deduction_authorized:
            if self.valuation_status != ValuationStatus.APPROVED:
                raise ValueError(f"Benefit {self.benefit_id}: Quà hiện vật chỉ được trừ giá khi có ValuationStatus.APPROVED.")
        return self
```

# 5. HỆ THỐNG CÔNG THỨC ĐỊNH GIÁ & DUAL DISCOUNT CAP (ADDITIVE MODEL)

Hệ thống khóa mô hình **Additive Discount Model** (Cộng dồn tỷ lệ trên cùng một giá cơ sở sau giảm trừ tiền mặt):

```text
       [GIÁ NIÊM YẾT GỐC (Listed Price: P_listed)]
                           │
                           ▼
 [BƯỚC 1: KHẤU TRỪ ƯU ĐÃI TIỀN MẶT CỐ ĐỊNH TRỰC TIẾP]
                 Base_1 = P_listed - D_fixed  (0 <= D_fixed <= P_listed)
                           │
                           ▼
 [BƯỚC 2: KHẤU TRỪ CHIẾT KHẤU TỶ LỆ % CỘNG DỒN (ADDITIVE)]
                 Sum_Rate = ∑ r_i  (với Sum_Rate <= max_discount_rate)
                 Discount_Percent_Amount = round_vnd(Base_1 * Sum_Rate)
                 P_net = Base_1 - Discount_Percent_Amount
                           │
                           ▼
 [BƯỚC 3: TÍNH THUẾ GTGT VÀ KINH PHÍ BẢO TRÌ TRÊN GIÁ NET]
                 A_vat  = round_vnd(P_net * R_vat)
                 A_kpbt = round_vnd(P_net * R_kpbt)
                           │
                           ▼
 [BƯỚC 4: TỔNG HỢP GIÁ TRỊ HỢP ĐỒNG CUỐI CÙNG]
                 P_contract = P_net + A_vat + A_kpbt
```

### Cơ chế Dual Discount Cap Bất biến:
1. **Trần tỷ lệ phần trăm gộp (Percentage Cap):**
   $$\text{Sum\_Rate} = \sum_{i \in \text{Approved}} r_i \le \text{max\_discount\_rate} \quad (0.3500)$$
2. **Trần tổng giá trị tài chính (Total Value Cap):**
   $$D_{\text{total}} = D_{\text{fixed}} + \text{Discount\_Percent\_Amount} \le \text{round\_vnd}\left( P_{\text{listed}} \times \text{max\_total\_discount\_cap\_rate} \right) \quad (0.4000)$$

# 6. ĐẶC TẢ LỊCH DÒNG TIỀN GENERIC ENGINE (POLICY-DRIVEN CASHFLOW)

Động cơ Cashflow là một **Generic Rule Iterator** độc lập, không hardcode logic theo tên kịch bản (`PA-CHUDONG`, `PA-VAY`). Mọi tham số tiến độ, vốn tự có và giải ngân ngân hàng đều nạp từ `PaymentScenarioConfig.installment_rules`.

### 6.1 Chuẩn hóa Ngữ nghĩa Tiền Cọc & Khái niệm `MIN_INITIAL_OUTFLOW`
- **`deposit_paid_vnd`:** Tiền cọc đã nộp trước khi ký HĐMB (Ví dụ: $100,000,000$ VNĐ).
- **`installment_gross_obligation_vnd`:** Tổng nghĩa vụ Đợt 1 theo quy định tiến độ:
  $$\text{gross}_1 = \text{round\_vnd}\left( (P_{\text{net}} + A_{\text{vat}}) \times \text{rule}_1.\text{customer\_equity\_ratio} \right) = 577,500,000 \text{ VNĐ}$$
- **`installment_additional_cash_due_vnd`:** Số tiền khách phải nộp thêm thực tế tại thời điểm ký HĐMB:
  $$\text{additional}_1 = \max(0, \text{gross}_1 - \text{deposit\_paid\_vnd}) = 577,500,000 - 100,000,000 = 477,500,000 \text{ VNĐ}$$
- **Khóa Định nghĩa `MIN_INITIAL_OUTFLOW`:** Là tổng dòng tiền mặt khách hàng tự chi trả từ đầu đến hết thời điểm hoàn thành nghĩa vụ Đợt 1:
  $$\text{INITIAL\_CASH\_OUTFLOW} \equiv \text{deposit\_paid\_vnd} + \text{installment\_additional\_cash\_due\_vnd} \equiv \text{gross}_1$$
  *(Với căn A-12-05: Cả `PA-CHUDONG` và `PA-VAY` đều có Gross Outflow = 577,500,000 VNĐ, gồm 100M cọc + 477.5M nộp thêm).*

### 6.2 Thuật toán Lập Dòng tiền Generic & Pure Reconciliation
```python
from datetime import timedelta

def generate_cashflow_schedule(
    scenario_config: PaymentScenarioConfig,
    net_price_before_vat: int,
    vat_amount: int,
    kpbt_amount: int,
    deposit_amount_vnd: int,
    deposit_date: date
) -> list[CashflowInstallmentOutput]:
    base_with_vat = net_price_before_vat + vat_amount
    contract_price = base_with_vat + kpbt_amount
    
    total_equity_target = round_vnd(Decimal(base_with_vat) * scenario_config.customer_equity_rate)
    total_bank_target = base_with_vat - total_equity_target  # Dual reconciliation
    
    schedule = []
    sum_equity_so_far = 0
    sum_bank_so_far = 0
    sum_kpbt_so_far = 0
    
    for rule in scenario_config.installment_rules:
        # Tính toán mốc ngày chính xác từ ngày đặt cọc
        due_date = deposit_date + timedelta(days=rule.days_from_deposit)
        
        if not rule.is_reconciliation:
            eq_amt = round_vnd(Decimal(base_with_vat) * rule.customer_equity_ratio)
            bank_amt = round_vnd(Decimal(base_with_vat) * rule.bank_disbursement_ratio)
            kpbt_amt = round_vnd(Decimal(net_price_before_vat) * rule.maintenance_fee_ratio)
        else:
            # Reconciliation Gate Tường minh: Bù triệt tiêu 1 đồng lẻ, đảm bảo không âm
            eq_amt = total_equity_target - sum_equity_so_far
            bank_amt = total_bank_target - sum_bank_so_far
            kpbt_amt = kpbt_amount - sum_kpbt_so_far
            
            if eq_amt < 0 or bank_amt < 0 or kpbt_amt < 0:
                raise ValueError(
                    f"CASHFLOW_RESIDUAL_ERROR: Đợt reconciliation sinh số dư âm: "
                    f"equity={eq_amt}, bank={bank_amt}, kpbt={kpbt_amt}."
                )
            
        sum_equity_so_far += eq_amt
        sum_bank_so_far += bank_amt
        sum_kpbt_so_far += kpbt_amt
        
        gross_milestone = eq_amt + bank_amt + kpbt_amt
        
        # Xử lý kết chuyển tiền cọc tại Đợt 1
        if rule.installment_number == 1:
            dep_credited = min(deposit_amount_vnd, eq_amt)
            add_cash_due = eq_amt - dep_credited
        else:
            dep_credited = 0
            add_cash_due = eq_amt
            
        schedule.append(CashflowInstallmentOutput(
            installment_number=rule.installment_number,
            milestone_name=rule.milestone_name,
            due_date=due_date,
            customer_equity_paid_vnd=eq_amt,
            bank_disbursement_vnd=bank_amt,
            maintenance_fee_paid_vnd=kpbt_amt,
            installment_gross_obligation_vnd=gross_milestone,
            installment_additional_cash_due_vnd=add_cash_due,
            deposit_credited_vnd=dep_credited,
            is_handover_milestone=rule.is_handover,
            is_reconciliation_installment=rule.is_reconciliation
        ))
        
    return schedule
```

# 7. GIẢI THUẬT XẾP HẠNG TỐI ƯU TẤT ĐỊNH (OPTIMIZATION & RANKING)

### 7.1 Danh mục 5 Mục tiêu Tối ưu hóa (Đồng bộ 100% với PRD v2.3)
1. **`MIN_NET_PRICE`:** Tối ưu Giá Net trước thuế thấp nhất ($P_{\text{net}}$).
2. **`MIN_CONTRACT_PRICE`:** Tối ưu Tổng Giá trị Hợp đồng Mua bán cuối cùng thấp nhất ($P_{\text{contract}}$).
3. **`MIN_INITIAL_OUTFLOW`:** Tối ưu Dòng tiền ban đầu khách hàng phải nộp đến hết Đợt 1 thấp nhất (`s.initial_cash_outflow_vnd`).
4. **`MIN_CASH_OUTFLOW_TO_HANDOVER`:** Tối ưu Tổng dòng tiền mặt thực tế do **KHÁCH HÀNG** chi trả từ lúc cọc đến hết thời điểm nhận bàn giao nhà:
   $$\text{Customer Outflow} = \sum_{k \le \text{Handover}} \left( \text{item}_k.\text{customer\_equity\_paid\_vnd} + \text{item}_k.\text{maintenance\_fee\_paid\_vnd} \right)$$
5. **`MAX_BENEFIT_VALUE`:** Tối ưu Tổng giá trị ưu đãi nhận được lớn nhất (chỉ tính quà có `ValuationStatus == APPROVED`).

### 7.2 Thuật toán Xếp hạng Kèm Canonical Scenario Order (Tie-Break)
```python
class OptimizationObjective(str, Enum):
    MIN_NET_PRICE = "MIN_NET_PRICE"
    MIN_CONTRACT_PRICE = "MIN_CONTRACT_PRICE"
    MIN_INITIAL_OUTFLOW = "MIN_INITIAL_OUTFLOW"
    MIN_CASH_OUTFLOW_TO_HANDOVER = "MIN_CASH_OUTFLOW_TO_HANDOVER"
    MAX_BENEFIT_VALUE = "MAX_BENEFIT_VALUE"

def rank_scenarios_by_objective(
    scenarios: list[ScenarioCalculationResult], 
    objective: OptimizationObjective
) -> list[ScenarioCalculationResult]:
    canonical_scenario_order = {
        ScenarioType.STANDARD_PROGRESS: 1,
        ScenarioType.EARLY_95: 2,
        ScenarioType.BANK_LOAN_HTLS: 3
    }
    
    if objective == OptimizationObjective.MIN_NET_PRICE:
        return sorted(scenarios, key=lambda s: (s.net_price_before_vat, s.final_contract_price, canonical_scenario_order[s.scenario_type]))
    elif objective == OptimizationObjective.MIN_CONTRACT_PRICE:
        return sorted(scenarios, key=lambda s: (s.final_contract_price, s.net_price_before_vat, canonical_scenario_order[s.scenario_type]))
    elif objective == OptimizationObjective.MIN_INITIAL_OUTFLOW:
        return sorted(scenarios, key=lambda s: (s.initial_cash_outflow_vnd, s.final_contract_price, canonical_scenario_order[s.scenario_type]))
    elif objective == OptimizationObjective.MIN_CASH_OUTFLOW_TO_HANDOVER:
        return sorted(scenarios, key=lambda s: (s.customer_cash_outflow_until_handover, s.final_contract_price, canonical_scenario_order[s.scenario_type]))
    elif objective == OptimizationObjective.MAX_BENEFIT_VALUE:
        return sorted(scenarios, key=lambda s: (-s.total_benefit_value_vnd, s.final_contract_price, canonical_scenario_order[s.scenario_type]))
```

# 9. CHỐT CHẶN KIỂM DUYỆT & BẤT BIẾN TÀI CHÍNH (VALIDATION & INVARIANTS)

```python
def validate_pricing_results(
    calc_result: ScenarioCalculationResult, 
    listed_price: int, 
    vat_rate: Decimal,
    maintenance_fee_rate: Decimal,
    max_discount_rate: Decimal,
    max_total_discount_cap_rate: Decimal
) -> ValidationReport:
    # 1. Cận dưới Giá Net
    if calc_result.net_price_before_vat <= 0:
        raise ValueError("SANITY_FAIL: Giá Net trước thuế phải lớn hơn 0.")

    # 2. Trần chiết khấu Dual Discount Cap
    if calc_result.total_discount_rate > max_discount_rate:
        raise ValueError(f"SANITY_FAIL: Tỷ lệ chiết khấu {calc_result.total_discount_rate} vượt trần {max_discount_rate}.")
        
    total_discount_vnd = calc_result.fixed_discount_vnd + calc_result.percentage_discount_vnd
    max_total_vnd = round_vnd(Decimal(listed_price) * max_total_discount_cap_rate)
    if total_discount_vnd > max_total_vnd:
        raise ValueError(f"SANITY_FAIL: Tổng chiết khấu {total_discount_vnd:,}đ vượt trần {max_total_vnd:,}đ.")

    # 3. Tính nhất quán VAT & KPBT (Không dùng magic numbers)
    expected_vat = round_vnd(Decimal(calc_result.net_price_before_vat) * vat_rate)
    if calc_result.vat_amount != expected_vat:
        raise ValueError(f"SANITY_FAIL: Thuế VAT sai lệch: {calc_result.vat_amount} vs kỳ vọng {expected_vat}.")

    expected_kpbt = round_vnd(Decimal(calc_result.net_price_before_vat) * maintenance_fee_rate)
    if calc_result.maintenance_fee_amount != expected_kpbt:
        raise ValueError(f"SANITY_FAIL: Phí KPBT sai lệch: {calc_result.maintenance_fee_amount} vs kỳ vọng {expected_kpbt}.")

    # 4. Cân bằng Tổng giá HĐMB
    if calc_result.final_contract_price != (calc_result.net_price_before_vat + expected_vat + expected_kpbt):
        raise ValueError("SANITY_FAIL: Tổng giá trị HĐ không bằng Net + VAT + KPBT.")

    # 5. Cân bằng Dòng tiền (Reconciliation Invariant)
    sum_installments = sum(item.installment_gross_obligation_vnd for item in calc_result.cashflow_schedule)
    if sum_installments != calc_result.final_contract_price:
        raise ValueError("SANITY_FAIL: Tổng các đợt thanh toán lệch với Tổng giá HĐMB.")

    return ValidationReport(is_valid=True, status="VALID", invariants_checked=[
        "INV-FIN-01: Net > 0",
        "INV-FIN-02: Contract == Net + VAT + KPBT",
        "INV-FIN-03: Sum Installments == Contract Price",
        "INV-FIN-04: Non-negative Installments",
        "INV-FIN-05: Additive Discount Formula Match"
    ])
```

# 11. BỘ KIỂM THỬ ĐẶC TÍNH TOÁN HỌC KÈM ĐIỀU KIỆN MIỀN (PROPERTY-BASED TESTS)

Hệ thống được kiểm định với thư viện `Hypothesis` trên không gian mẫu $N = 10,000$ test cases ngẫu nhiên thỏa mãn 10 đặc tính toán học kèm điều kiện tiên quyết (Preconditions):

1. **Property 1 (Reconciliation Completeness):**  
   *Precondition:* Cấu hình kịch bản có đúng 1 đợt reconciliation và tổng tỷ lệ phân bổ hợp lệ.  
   *Assertion:* $\sum_{k=1}^N \text{installment\_gross\_obligation\_vnd}_k \equiv P_{\text{contract}}$ với mọi $P_{\text{listed}} \in [10^9, 5 \times 10^{10}]$ VNĐ.
2. **Property 2 (Non-negativity):**  
   *Precondition:* Giá niêm yết $P_{\text{listed}} > 0$, tổng chiết khấu không vượt trần cho phép.  
   *Assertion:* $\forall k \in [1, N]: \text{installment\_gross\_obligation\_vnd}_k \ge 0$.
3. **Property 3 (Price Monotonicity):**  
   *Precondition:* Giữ nguyên toàn bộ tập ưu đãi hợp lệ, cùng phiên bản chính sách, cùng cấu hình kịch bản, và không có chính sách bậc thang (threshold policy).  
   *Assertion:* $P_{\text{listed}}^{(A)} > P_{\text{listed}}^{(B)} \implies P_{\text{contract}}^{(A)} > P_{\text{contract}}^{(B)}$.
4. **Property 4 (Discount Monotonicity):**  
   *Precondition:* Cùng giá niêm yết gốc, các ưu đãi cùng calculation base, tỷ lệ tăng không làm thay đổi tính hợp lệ và không vượt trần chiết khấu.  
   *Assertion:* $\sum r_i^{(A)} \ge \sum r_i^{(B)} \implies P_{\text{net}}^{(A)} \le P_{\text{net}}^{(B)}$.
5. **Property 5 (Permutation Invariance):**  
   *Precondition:* Các kịch bản có định danh phân biệt hoặc tuân theo thứ tự tie-break quy định.  
   *Assertion:* $\text{Rank}(A, B, C) \equiv \text{Rank}(C, A, B)$ (Đề xuất tối ưu bất biến trước thứ tự danh sách đầu vào).
6. **Property 6 (Deterministic Idempotency):**  
   *Precondition:* Cùng `PricingCalculationInput` bất kể thứ tự key JSON, cùng giá trị Decimal biểu diễn, process restart hoặc reload từ JSON.  
   *Assertion:* Luôn luôn trả về `PricingCalculationOutput` với `canonical_snapshot_hash` trùng khớp $100\%$.
7. **Property 7 (Non-negative Residual):**  
   *Precondition:* Thuật toán phân bổ đợt cuối: $\text{residual} = P_{\text{contract}} - \sum_{k=1}^{N-1} \text{gross}_k$.  
   *Assertion:* $\text{residual} \ge 0$. Nếu residual âm, engine bắt buộc ném lỗi `CashflowResidualError`, tuyệt đối không tự ép về 0.
8. **Property 8 (Funding Breakdown Exact Sum):**  
   *Precondition:* Kịch bản phân bổ vốn bất kỳ thỏa mãn invariant đầu vào.  
   *Assertion:* $\sum \text{customer\_equity\_paid\_vnd} \equiv \text{total\_equity\_target}$ và $\sum \text{bank\_disbursement\_vnd} \equiv \text{total\_bank\_target}$.
9. **Property 9 (Deposit Credit Invariant):**  
   *Precondition:* Tiền cọc đã nộp `deposit_amount_vnd >= 0`.  
   *Assertion:* $\text{deposit\_credited\_vnd} \le \text{deposit\_amount\_vnd}$ và $\text{additional\_cash\_due} + \text{deposit\_credited} \equiv \text{customer\_equity\_paid}$.
10. **Property 10 (Canonical Hash Sensitivity):**  
   *Precondition:* Hai input chỉ khác nhau đúng 1 bit ở bất kỳ trường nào (`unit_code`, `date`, `rates`, `clause_id`).  
   *Assertion:* $\text{hash}(Input_A) \ne \text{hash}(Input_B)$ (Độ nhạy tuyệt đối của mã băm kiểm toán).
